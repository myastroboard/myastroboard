## Points of attention

- **url-normalize 4.0.0** (transitive, through `requests-cache`, which accepts `>=2.0`): not pinned
  by the project, so the next Docker build installs it whatever this branch does. It is a breaking
  release (query escapes such as `%2F` / `%2C` are now preserved, among others). It was installed
  in the local environment and the suite passes with it. Every `requests-cache` key of the
  Open-Meteo client changes (checked on three typical URLs), so after the first deploy each
  location's weather is fetched once from Open-Meteo instead of the 1-hour cache. No error, but the
  old entries stay in `data/cache/.weather_cache.sqlite` until they are cleaned up.
- **Intermittent e2e failures, pre-existing**: across 9 full e2e runs (4 with Chart.js 4.6.1, 5
  with 4.6.2), failing runs hit `test_navigation.py::test_reloading_the_page_keeps_the_active_tab`,
  `test_modals.py` tests, `test_session_analytics_sky_chart.py::test_sky_chart_renders_with_its_month_axis`,
  and one `net::ERR_ADDRESS_IN_USE` setup error (Windows ephemeral port). The reload test has a race
  in the test itself: it reads the active sub-tab as soon as the main tab is active, while the
  sub-tab is restored 10 to 90 ms later (measured with a temporary waiting variant, since removed).
  Fixing it (wait for the sub-tab selector) is a follow-up outside this update.
- **Manual check advised**: a few Chart.js charts (weather, altitude-time popup, analytics) on a
  desktop and a phone, in each theme. A headless check drew line, bar and doughnut charts with
  4.6.2 without console errors, and a responsive chart shrank and grew back with its container.
- **js2py** 0.74 (PYSEC-2026-1476): still pulled by `translators` -> `ai-cloudscraper`, dev-only
  (`scripts/translate_i18n_values.py`), not in `requirements.txt` nor the Docker image. No fixed
  version yet.
