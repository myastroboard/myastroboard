# Organization

How the repository and the runtime data are laid out, and how a request and a SkyTonight run flow
through them. Read this before adding a module; the rules for where new code goes are in
[EXTENDING.md](EXTENDING.md).

## Architecture at a glance

```
                        Browser (static/js, one module per feature)
                                        |
                                        v
  backend/app.py  ->  backend/blueprints/*.py  (every HTTP route, one Blueprint per domain)
                                        |
             +--------------------------+---------------------------+
             v                          v                           v
   feature packages              cache/cache_store         db/ (SQLite, Alembic)
   (skytonight, observation,     per-location JSON          accounts, configuration,
    equipment, weather, ...)     slots with a TTL each      every per-user record
             ^                          ^
             |                          |
   skytonight_scheduler          cache_scheduler            push_scheduler, mqtt_publisher,
   (twice a night, writes        (every 25 min, runs only   mqtt_subscriber
    data/skytonight/)             the jobs whose TTL ran out) (background threads)
```

- Routes never compute anything heavy: they read what the background threads wrote, from the
  cache or from `data/skytonight/`.
- Feature packages never import blueprints; a helper needed by two features lives in `utils/`.
- Per-user data lives in the database, never in a JSON file
  ([DATABASE.md](DATABASE.md), [PRIVACY.md](PRIVACY.md)).

## Runtime data (`data/`)

```text
data/
├── myastroboard.db                  # SQLite: accounts, configuration, settings, session and VAPID keys,
│                                    #   Astrodex, equipment, plans, observation log, wishlist
├── myastroboard.log (+ .1 ... .5)   # Application log, rotated at 10 MB
├── astrodex/images/                 # Astrodex pictures (<user_id>_...)
├── observation_sessions/attachments/ # Observation Log attachments (<user_id>_...)
├── backups/                         # Pre-1.7 JSON archive and import report (1.7 upgrade only)
├── cache/
│   ├── astro_cache.json             # Shared cache slots ("<job>:<location_id>")
│   ├── iers/, skyfield/             # Earth orientation data, planetary ephemeris
│   ├── map_tiles/                   # OpenStreetMap tiles, glyphs, sprites
│   ├── object_images/, framing_images/ # DSS2 sky images (capped at 200 MiB)
│   └── spaceflight_images/          # Launch and astronaut pictures
└── skytonight/
    ├── catalogues/targets.json      # Built deep-sky dataset
    ├── calculations/                # Tonight's results (dso, bodies, comets, sky map)
    ├── outputs/                     # Altitude-vs-time series per target
    ├── logs/last_calculation.log    # Last run log
    └── runtime/                     # Scheduler status, trigger file, lock
```

Never delete `data/myastroboard.db` (or its `-wal` / `-shm` companions while the app runs): it also
holds the session key and the VAPID keys, and a new VAPID key silently breaks every push
subscription.

## Key data flows

```
Browser request
  └─ backend/blueprints/<domain>.py
       ├─ @login_required / @admin_required (utils/auth.py)
       ├─ location of the request: utils/route_helpers._resolve_active_location()
       ├─ cache hit  -> cached JSON for that location (cache/cache_store.py)
       └─ cache miss -> "pending" until the background scheduler fills the slot

cache/cache_scheduler.py (every 25 min)
  └─ cache/cache_updater.py: each job x each location whose TTL ran out
       ├─ astroweather/* (moon, sun, eclipses, aurora, horizon, seeing)
       ├─ weather/* (Open-Meteo, astro-analysis), space/* (ISS, CSS, launches)
       └─ observation/* (planetary events, phenomena, solar system events)

skytonight/skytonight_scheduler.py (startup, 1 h after nautical dawn, 1 h before nautical dusk)
  └─ skytonight_calculator.run_calculations()
       ├─ targets.json + comets + bodies
       ├─ observability, AstroScore, difficulty per target
       └─ data/skytonight/calculations/*.json, outputs/<target_id>_alttime.json
```
